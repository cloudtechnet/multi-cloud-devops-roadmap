# AWS DHCP Option Set

**DHCP Option Set** in AWS VPC is used to provide **network configuration information to EC2 instances** when they are launched inside a VPC.

In simple words:

> **DHCP Option Set tells EC2 instances which DNS server, domain name, and other network settings they should use.**

---

## 1. Why do we need DHCP Option Set?

When an EC2 instance starts, it needs some basic network information such as:

* DNS server
* Domain name
* NTP server
* NetBIOS settings, if required

AWS provides a **default DHCP Option Set** for every VPC.

Typical AWS default settings include:

```text
Domain Name:
<region>.compute.internal

Domain Name Servers:
AmazonProvidedDNS
```

For example, in an AWS region, EC2 instances can use the AWS-provided DNS resolver to resolve names such as:

```text
google.com
amazon.com
database.internal
```

---

# 2. Simple Architecture

```text
                 AWS VPC
        CIDR: 10.0.0.0/16
                  |
          DHCP Option Set
                  |
        +---------+---------+
        |                   |
   Private Subnet       Private Subnet
   10.0.1.0/24          10.0.2.0/24
        |                   |
     EC2-01              EC2-02
        |                   |
        +---------+---------+
                  |
             DNS Resolver
        AmazonProvidedDNS
```

The DHCP Option Set provides the network configuration to instances through DHCP.

---

# 3. Real-World Example

Imagine you have a company called:

**Cloud Technet**

You create an AWS VPC:

```text
VPC CIDR
10.0.0.0/16
```

Your company wants EC2 servers to use a custom internal DNS domain:

```text
cloudtechnet.local
```

And you have a DNS server:

```text
10.0.10.10
```

You can create a DHCP Option Set like:

```text
Domain name:
cloudtechnet.local

Domain name servers:
10.0.10.10
```

Then associate this DHCP Option Set with your VPC.

### Architecture

```text
                 Cloud Technet VPC
                   10.0.0.0/16
                        |
              DHCP Option Set
                        |
          +-------------+-------------+
          |                           |
      EC2 Web Server             EC2 App Server
       10.0.1.10                  10.0.1.20
          |                           |
          +-------------+-------------+
                        |
                  DNS Server
                  10.0.10.10
                        |
              cloudtechnet.local
```

Now your EC2 instances can use the configured DNS server for name resolution.

For example:

```text
app.cloudtechnet.local
        ↓
    10.0.1.20
```

---

# 4. Important DHCP Options

The commonly used options are:

| Option                   | Purpose                            | Example              |
| ------------------------ | ---------------------------------- | -------------------- |
| **Domain name**          | Defines the DNS search/domain name | `cloudtechnet.local` |
| **Domain name servers**  | Defines DNS servers                | `10.0.10.10`         |
| **NTP servers**          | Defines time servers               | `10.0.10.20`         |
| **NetBIOS name servers** | Used mainly for Windows networking | `10.0.10.30`         |
| **NetBIOS node type**    | Controls NetBIOS behavior          | `2`                  |

For most AWS environments, the important one is:

```text
Domain Name Servers
```

---

# 5. AWS Default DHCP Option Set

When you create a VPC, AWS automatically creates a default DHCP Option Set.

Conceptually:

```text
VPC
10.0.0.0/16
   |
   +---- DHCP Option Set
           |
           +-- Domain Name
           +-- AmazonProvidedDNS
```

The AWS-provided DNS resolver is reachable using the VPC's **VPC+2 address**.

For example:

```text
VPC CIDR: 10.0.0.0/16

Network address: 10.0.0.0
VPC DNS resolver: 10.0.0.2
```

So EC2 instances can use:

```text
10.0.0.2
```

as the DNS resolver in this example.

---

# 6. Important Point

A DHCP Option Set **does not assign the EC2 private IP address itself**.

Think of the responsibilities like this:

```text
DHCP
 |
 +-- IP configuration
 +-- DNS configuration
 +-- Domain information
 +-- NTP information
```

Whereas:

```text
Route Table
     ↓
Controls where network traffic goes

Security Group
     ↓
Controls allowed inbound/outbound traffic

NACL
     ↓
Controls subnet-level traffic

DHCP Option Set
     ↓
Provides network configuration information
```

## 7. Easy Real-World Analogy

Think about an office.

When a new employee connects a laptop to the company network, the network can automatically tell the laptop:

```text
Your IP address → 10.10.1.25
DNS Server      → 10.10.1.10
Domain          → company.local
NTP Server      → 10.10.1.20
```

In AWS, **DHCP Option Set provides similar network configuration information to resources in the VPC.**

### Remember this for interviews:

> **AWS DHCP Option Set is a VPC-level configuration that provides DHCP network settings such as DNS servers, domain name, NTP servers, and NetBIOS settings to instances in the VPC.**
