# AWS NAT Gateway — Complete Explanation with Real-World Example

## 1. What is a NAT Gateway?

**NAT Gateway (Network Address Translation Gateway)** is an AWS service that allows resources in a **private subnet** to access the **internet for outbound communication**, while preventing the internet from directly initiating connections to those resources.

### Simple definition

> **NAT Gateway allows Private Subnet → Internet communication, but Internet → Private Subnet communication is not allowed by the NAT Gateway.**

For example, your application server is in a private subnet and needs to download packages from the internet.

```text
Private EC2
    |
    | Request
    ↓
NAT Gateway
    |
    ↓
Internet Gateway
    |
    ↓
Internet
```

---

# 2. Why do we need NAT Gateway?

Suppose we have an application running on an EC2 instance.

For security reasons, we don't want to give the EC2 instance a **public IP address**.

But the application may still need to:

* Download Linux packages
* Download security updates
* Pull Docker images
* Access GitHub
* Call external APIs
* Download application dependencies
* Connect to AWS services through public endpoints

The EC2 instance is in a **private subnet**.

So how can it access the internet?

👉 **NAT Gateway**

---

# 3. Real-World Example — E-Commerce Application

Let's take your **QuickKart / Zepto-style e-commerce application** as an example.

Suppose we have:

```text
                 INTERNET
                     |
                     |
             Internet Gateway
                     |
              ┌──────┴──────┐
              │             │
         Public Subnet   Private Subnet
              │             │
        NAT Gateway       EC2 App
              │             │
              └─────────────┘
```

A better architecture is:

```text
                         INTERNET
                             |
                             |
                    Internet Gateway
                             |
                  ┌──────────┴──────────┐
                  |                     |
            Public Subnet          Private Subnet
                  |                     |
            NAT Gateway              EC2
                  |               Application
                  |                     |
                  └───────OUTBOUND─────┘
```

### Example:

Your application server needs to install Node.js packages:

```bash
npm install
```

The EC2 instance needs to communicate with:

```text
registry.npmjs.org
```

But the EC2 instance does **not** have a public IP.

Therefore:

```text
EC2 Private Subnet
       |
       | npm request
       ↓
NAT Gateway
       |
       ↓
Internet Gateway
       |
       ↓
Internet
       |
       ↓
npm Registry
```

The response comes back through the NAT Gateway to the EC2 instance.

# 4. Important Point — NAT Gateway is placed in Public Subnet

This is one of the most important concepts.

A NAT Gateway should be created in a **Public Subnet**.

Why?

Because the NAT Gateway itself needs a path to the internet.

Architecture:

```text
                  INTERNET
                     |
              Internet Gateway
                     |
              Public Route Table
                     |
              Public Subnet
                     |
                NAT Gateway
                     |
              Private Route Table
                     |
              Private Subnet
                     |
                  EC2
```

---

# 5. What is required to create NAT Gateway?

Normally, you need:

### 1. VPC

Example:

```text
VPC CIDR
10.0.0.0/16
```

### 2. Public Subnet

Example:

```text
10.0.1.0/24
```

### 3. Private Subnet

Example:

```text
10.0.2.0/24
```

### 4. Internet Gateway

Connected to the VPC.

### 5. Elastic IP

NAT Gateway requires an **Elastic IP address** for public internet access.

### 6. Route Tables

You need separate routing logic for public and private subnets.

# 6. Complete Architecture

Let's create a simple architecture.

```text
                         INTERNET
                             |
                             |
                    ┌─────────────────┐
                    │ Internet Gateway│
                    └────────┬────────┘
                             |
                 ┌───────────┴───────────┐
                 |                       |
          PUBLIC SUBNET             PRIVATE SUBNET
          10.0.1.0/24               10.0.2.0/24
                 |                       |
                 |                  ┌──────────┐
                 |                  │   EC2    │
                 |                  │ App      │
                 |                  └────┬─────┘
                 |                       |
          ┌─────────────┐                |
          │ NAT Gateway │◄───────────────┘
          └──────┬──────┘
                 |
                 └──────── Internet
```

Actually, the routing path for private EC2 outbound traffic is:

```text
EC2
 ↓
Private Route Table
 ↓
NAT Gateway
 ↓
Public Route Table
 ↓
Internet Gateway
 ↓
Internet
```

# 7. Route Table Configuration

This is where students usually get confused.

## Public Route Table

Public subnet route table:

| Destination | Target           |
| ----------- | ---------------- |
| 10.0.0.0/16 | local            |
| 0.0.0.0/0   | Internet Gateway |

Meaning:

```text
Public Subnet
      |
      └── 0.0.0.0/0
             ↓
       Internet Gateway
```

---

## Private Route Table

Private subnet route table:

| Destination | Target      |
| ----------- | ----------- |
| 10.0.0.0/16 | local       |
| 0.0.0.0/0   | NAT Gateway |

Meaning:

```text
Private Subnet
      |
      └── 0.0.0.0/0
             ↓
        NAT Gateway
```

This is the key configuration.

# 8. How the Request Actually Travels

Suppose:

```text
EC2 Private IP:
10.0.2.10
```

The EC2 wants to access:

```text
https://google.com
```

### Step 1 — EC2 sends request

```text
Source:
10.0.2.10

Destination:
Google Internet IP
```

### Step 2 — Private Route Table

The route table says:

```text
0.0.0.0/0 → NAT Gateway
```

So traffic goes to the NAT Gateway.

### Step 3 — NAT Gateway performs NAT

The NAT Gateway translates the private source address to its public Elastic IP.

For example:

```text
Before NAT:

10.0.2.10 → Google

After NAT:

52.x.x.x → Google
```

Here:

```text
10.0.2.10
     ↓
NAT Gateway
     ↓
52.x.x.x
```

### Step 4 — Internet Gateway

The traffic goes through the Internet Gateway to the internet.

### Step 5 — Response

Google sends the response back to:

```text
52.x.x.x
```

The NAT Gateway knows which private EC2 initiated the request and sends the response back to:

```text
10.0.2.10
```

---

# 9. Very Important — NAT Gateway is Outbound Only

Consider:

```text
Private EC2
     |
     ↓
NAT Gateway
     |
     ↓
Internet
```

The EC2 can initiate:

```text
EC2 → Internet
```

But an external user cannot directly initiate:

```text
Internet → Private EC2
```

through the NAT Gateway.

That's why NAT Gateway is commonly used for private application servers.

# 11. NAT Gateway vs Internet Gateway

This is an important interview question.

| Feature             | Internet Gateway                                             | NAT Gateway                             |
| ------------------- | ------------------------------------------------------------ | --------------------------------------- |
| Purpose             | Internet connectivity                                        | Private subnet outbound internet        |
| Used by             | Public resources                                             | Private resources                       |
| Public IP required  | Resource normally needs public IP for direct internet access | NAT Gateway uses Elastic IP             |
| Internet → resource | Possible if security/routing allows                          | Not for unsolicited inbound connections |
| Location            | Attached to VPC                                              | Created in public subnet                |
| NAT                 | No                                                           | Yes                                     |

### Simple memory trick

> **Internet Gateway = Public Subnet Internet Access**

> **NAT Gateway = Private Subnet Outbound Internet Access**

---

# 12. NAT Gateway vs NAT Instance

AWS also has a concept called **NAT Instance**.

### NAT Gateway

```text
AWS Managed Service
```

Advantages:

* Highly available within an Availability Zone
* AWS manages it
* No OS administration
* Supports high bandwidth
* Easier to operate

### NAT Instance

```text
EC2 Instance configured as NAT
```

You have to manage:

* OS
* Patching
* Scaling
* Failover
* Security
* Availability

For modern AWS architectures, **NAT Gateway is commonly preferred** when managed NAT functionality is required.

---

# 13. High Availability Architecture

For production environments, you should think about Availability Zones.

Example:

```text
                 Internet
                    |
             Internet Gateway
                    |
        ┌───────────┴───────────┐
        |                       |
       AZ-1                    AZ-2
        |                       |
 Public Subnet             Public Subnet
        |                       |
 NAT Gateway 1             NAT Gateway 2
        |                       |
 Private Subnet            Private Subnet
        |                       |
    EC2/App                  EC2/App
```

Each NAT Gateway is placed in its own AZ.

This avoids making one NAT Gateway a single point of dependency for multiple AZs.

---

# 14. Cost Consideration

NAT Gateway is **not free**.

You generally pay for:

* NAT Gateway hourly usage
* Data processed through the NAT Gateway

So if an application transfers a large amount of traffic through NAT Gateway, the cost can become significant.

For AWS services, architecture can sometimes be optimized by using services such as **VPC endpoints** where appropriate, so traffic to supported AWS services does not need to traverse a NAT Gateway.

# 15. Interview Answer

If an interviewer asks:

**"What is a NAT Gateway?"**

You can answer:

> "NAT Gateway is an AWS managed service that allows instances in a private subnet to access the internet for outbound communication without giving those instances public IP addresses. We create the NAT Gateway in a public subnet and associate an Elastic IP with it. The private subnet route table sends 0.0.0.0/0 traffic to the NAT Gateway, and the NAT Gateway sends the traffic through the Internet Gateway. For example, a private EC2 application server can use NAT Gateway to download packages or call external APIs while remaining inaccessible directly from the internet."
