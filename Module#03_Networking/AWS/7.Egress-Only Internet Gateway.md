## AWS Egress-Only Internet Gateway

An **Egress-Only Internet Gateway (EIGW)** is an AWS VPC component that allows **IPv6 resources in a private subnet to initiate outbound connections to the internet**, while **preventing the internet from initiating inbound connections** to those resources.

Think of it as a **one-way internet door**:

> **Private IPv6 Server → Internet ✅**
> **Internet → Private IPv6 Server ❌**

### Simple Architecture

```text
                    INTERNET
                       🌐
                       │
              Outbound IPv6 traffic
                       │
                       ▼
        ┌──────────────────────────┐
        │ Egress-Only Internet     │
        │ Gateway (EIGW)           │
        └──────────────────────────┘
                       │
                       │
              ┌───────────────┐
              │     AWS VPC   │
              │  10.0.0.0/16  │
              │               │
              │ Private Subnet│
              │  IPv6 Enabled │
              │               │
              │  EC2 Server   │
              └───────────────┘
```

### Real-World Example

Suppose you have an **EC2 application server** with an IPv6 address.

The server needs to:

* Download software updates
* Access an external API
* Pull application data from the internet

But you **do not want internet users to directly connect to the server**.

You can configure:

```text
EC2 Instance
     │
     │ IPv6 outbound
     ▼
Private Subnet
     │
     ▼
Egress-Only Internet Gateway
     │
     ▼
Internet
```

The EC2 instance can make:

```text
EC2 → api.example.com       ✅
EC2 → GitHub                ✅
EC2 → Software repository   ✅
```

But:

```text
Internet → EC2              ❌
```

### EIGW vs Internet Gateway

| Feature          | Internet Gateway           | Egress-Only IGW        |
| ---------------- | -------------------------- | ---------------------- |
| IPv4             | ✅                          | ❌                      |
| IPv6             | ✅                          | ✅                      |
| Outbound traffic | ✅                          | ✅                      |
| Inbound traffic  | ✅                          | ❌                      |
| Stateful         | No NAT behavior            | Stateful               |
| Typical use      | Public IPv4/IPv6 resources | Private IPv6 resources |

### Important Point

**Egress-Only Internet Gateway is specifically for IPv6.**

For IPv4 private subnets, you normally use a **NAT Gateway**:

```text
IPv4 Private EC2
      ↓
NAT Gateway
      ↓
Internet Gateway
      ↓
Internet
```

For IPv6:

```text
IPv6 Private EC2
      ↓
Egress-Only Internet Gateway
      ↓
Internet
```

### Route Table

For the IPv6 private subnet, you add a route such as:

```text
Destination
::/0

Target
eigw-xxxxxxxx
```

`::/0` means **all IPv6 addresses**.

So the basic flow is:

```text
EC2
 │
 │ IPv6
 ▼
Private Subnet
 │
 │ Route: ::/0
 ▼
Egress-Only Internet Gateway
 │
 ▼
Internet
```

**Easy way to remember:**

> **NAT Gateway → IPv4 private outbound access**
> **Egress-Only Internet Gateway → IPv6 private outbound access**
